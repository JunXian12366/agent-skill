# PMP Java 分析与诊断

如果可以访问 `..\..\copilot-instructions.md`，请遵循其中的共享约束；此处引用不会自动激活这些约束。

## 操作步骤
1. 明确待解答的问题，或预期行为与实际行为的差异、受影响的路由/类，以及现有错误信息或复现证据。默认仅分析。
2. 仅追踪相关的 controller -> service -> Feign/model 调用路径，以及适用的异常处理和配置逻辑。对于流程问题，应解释调用路径，不要凭空认定存在缺陷。
3. 区分已确认的观察结果与假设。按可能性排列原因，并找出能够区分这些原因的最小安全检查。
4. 优先使用已有日志或可用的隔离检查。运行任何测试前先检查其内容；只有调试器可用且本地复现已获授权时，才使用调试器。不得编造运行时证据。
5. 建议有针对性的下一步。若用户明确要求修复，则在授权范围内进行聚焦修正并执行回归检查。

## 任务边界
- 仅分析意味着不得修改源码、测试或配置。
- 未经批准，不得为了复现问题而启动应用、连接真实服务或访问生产环境。
- 依赖解析或凭据失败属于环境阻碍，并不能证明应用存在缺陷。

## 证据与完成标准
提供相关流程、证据位置、置信程度、尚未确定的事项及建议行动。只有证据充分支持时，才能断定根因。若已获授权进行修复，应列出修改的文件和实际验证结果；否则以调查结论结束任务，不做修改。
