# SQL Server 转 MySQL 存储过程

先读取目标目录适用的项目指令。如果可以访问相对于本技能目录的 `..\..\copilot-instructions.md`，也应读取其中的共享约束；此处引用不会自动加载文件。本技能生成 SQL 脚本，不将 Java/Feign 分层规则机械套用到存储过程。

## 输入与范围
- 确定源 SQL 文件或代码片段、目标过程名称、输出目录及 MySQL 目标版本。优先从用户说明和现有配置确定版本；无法确定时询问，不假定 MySQL 与 MariaDB 兼容，也不擅自要求升级数据库。
- 确定目标数据库及表、列、函数的映射，关注大小写、字符集、排序规则、时区和 `sql_mode`。只针对影响实际转换的缺失信息提问，不要求每项任务先审批计划。
- 明确“调用”是指过程内部调用的对象，还是调用该过程的语句/调用方；能从上下文判断时直接处理，否则先澄清。不得将注释中的示例或旧调用当作实际依赖。
- 只转换指定对象及必要依赖。遇到同名不同 schema、动态对象名或缺失依赖时说明影响，不凭空补建表、函数或业务规则。
- 如果用户指定 CN/CM/HK 等来源与输出目录映射，严格按映射分别处理，不能因为过程名称相同就混用地区版本。没有明确授权，不合并地区逻辑。

## 操作步骤
1. 完整读取目标过程及相关批次头，识别源文件编码；沿实际调用链检查必要的过程、函数及表结构，直到依赖可以明确映射。区分实际代码、字符串中的动态 SQL 和注释，不用全局正则替换充当转换。
2. 在工作上下文建立源对象与目标对象对应清单，记录参数顺序、类型、默认值、输出参数、返回码、结果集、分支、过滤、连接、排序、分页、金额运算、事务及所有写入和日志副作用，不额外创建说明文件。
3. 搜索目标目录已有的 MySQL 同类实现，复用约定和已转换依赖。先确定不能直接等价转换的语义及调用契约；实质性行为变更必须获得用户确认。
4. 按依赖关系生成完整的 MySQL 过程/函数及用户要求的调用脚本。参数和局部变量采用目标约定；无既有约定时分别使用 `p_`、`v_` 前缀，列引用使用表别名，避免名称遮蔽。
5. 逐项对照下方语义核对表完成转换，不用 TODO、空实现、固定返回值、静默跳过或删减分支冒充完成。源依赖不足时保留源文件，明确列出尚未完成的对象与原因。
6. 所有对象写完后集中检查，并再次从源过程逐段追踪输入到输出及副作用，确认每个分支、函数调用、结果列和异常路径都有对应实现。
7. 交付时简述输出位置、对象及调用映射、需要调用方配合的变化和剩余阻碍。只有实际获得证据时才说明运行结果一致；静态检查不能证明数据库运行时等价。

## T-SQL 与 MySQL 语义核对

### 定义、参数和调用契约
- 将 `CREATE/ALTER PROCEDURE`、`AS`、`BEGIN/END` 转换为目标版本支持的定义。去除 SQL Server 专用的 `GO`、`SET ANSI_NULLS`、`SET QUOTED_IDENTIFIER`、`SET NOCOUNT ON` 等，逐项确认它们涉及的语义，而非只删除文本。
- `[dbo].[对象]` 和多段名称必须按实际数据库/schema 映射处理；MySQL 的 schema 即 database，不能机械替换为 `dbo` 数据库。标识符按需使用反引号，保留目标表名大小写。
- 将输入、输出和双向参数准确映射为 `IN`、`OUT`、`INOUT`。SQL Server 的 `OUTPUT` 参数可能兼具输入用途，必须检查读取和赋值行为，不能统一改为 `OUT`。
- SQL Server 参数默认值、命名参数调用、过程整数 `RETURN` 码不能假定在目标版本有直接对应。需要调用方显式传值、包装过程或额外输出参数时先明确契约；不得把“未传参数”与“显式传 NULL”混为一谈。
- 普通过程调用使用 `CALL`，标量函数使用表达式调用。保持参数位置和输出参数获取方式；示例只用占位符或合成数据，放在单独的调用脚本中，不随定义自动执行。
- 保持结果集数量、输出列名称与顺序、类型和排序要求。中间变量赋值不能误写成产生额外结果集的 `SELECT`。

### 类型、字符串和数值
- 按值域与用途映射 `bit`、`int`、`bigint`、`decimal`、`money`、`nvarchar`、`varchar(max)`、`varbinary`、`uniqueidentifier` 等。明确长度、字符集、精度和 scale；GUID 的文本或二进制存储必须匹配目标表，不擅自选型。
- SQL Server `timestamp/rowversion` 是版本标记，不是日期时间，不能改成 MySQL `TIMESTAMP`。`datetime`、`datetime2`、`datetimeoffset` 按精度和时区需求选取目标表示。
- `ISNULL`、`COALESCE`、`IIF`、`CASE`、`CAST/CONVERT` 的映射须检查类型推导与隐式转换。金额不能用浮点数中转，保留整数除法、舍入、溢出与除零语义。
- 字符串 `+` 不能机械改为 `CONCAT`：检查 NULL 传播、数值相加和源会话设置。检查 `LEN` 与 `CHAR_LENGTH` 对尾部空格的区别，以及空字符串、大小写、重音、中文和排序规则。
- `LIKE` 的字符范围、转义、`PATINDEX`、`CHARINDEX`、`STUFF`、`STRING_SPLIT`、`STRING_AGG` 等逐项实现；不能假定 MySQL 的匹配和聚合函数在顺序、去重、NULL、长度截断方面等价。

### 日期、查询和临时数据
- `GETDATE/GETUTCDATE`、`DATEADD`、`DATEDIFF`、`DATEPART`、`DATENAME`、`EOMONTH`、`CONVERT` 日期样式按实际语义转换。T-SQL `DATEDIFF` 统计指定日期部分的边界跨越，不能机械替换成按完整时长计算的 `TIMESTAMPDIFF`。
- 保留日期区间的开闭边界、日期截断、月末、闰年、周起始日、时区和格式化语言；禁止依赖未确认的服务器区域设置。
- 将 `TOP`、分页转换为有相同排序语义的 `LIMIT/OFFSET`；检查 `TOP WITH TIES/PERCENT`、NULL 排序和无排序查询的不确定性。需要新增稳定排序规则时不能擅自决定业务顺序。
- 检查 CTE、递归 CTE、窗口函数、`APPLY`、`PIVOT/UNPIVOT`、`FULL OUTER JOIN`、`SELECT INTO`、多表更新及删除在目标版本中的可用性。改写时保留重复行、NULL 扩展、连接基数和聚合边界。
- `MERGE` 不能直接视为 `INSERT ... ON DUPLICATE KEY UPDATE`，需核对唯一键、匹配条件、删除分支和并发行为。`OUTPUT` 子句、`SCOPE_IDENTITY()`、`@@ROWCOUNT` 等必须保留其捕获范围与时机。
- 表变量、表值参数、表值函数及 `#temp/##temp` 无通用的一对一映射。根据调用契约选择临时表、集合输入或查询改写；处理会话隔离、连接池复用、重复调用、递归/嵌套调用的同名冲突与异常清理。
- 检查 `SELECT @变量 = 列` 与 `SELECT ... INTO` 在零行、多行时的差异，禁止为消除报错随意加 `LIMIT 1`。检查 `ONLY_FULL_GROUP_BY`，不得用关闭严格模式掩盖查询问题。

### 临时表与 ERROR 1137（Can't reopen table）
- 将临时表兼容性作为转换的必查项。MySQL 用户创建的 `TEMPORARY TABLE` 在同一条查询中被多次引用可能触发 `ERROR 1137: Can't reopen table`；这不同于重复创建导致的“表已存在”，不能靠 `DROP ... IF EXISTS` 或 `CREATE ... IF NOT EXISTS` 修复。
- 按完整 SQL 语句统计实际临时表引用，而不是仅统计别名或单个查询块。检查自连接、多次 JOIN、外层查询与子查询、多个 `EXISTS/IN`、`UNION/UNION ALL` 分支、CTE/派生表展开，以及动态 SQL。结合调用链检查存储函数中重复引用临时表的额外限制，以目标 MySQL 版本为准。
- 优先在保持重复行、NULL、聚合和过滤语义的前提下，改写为只扫描该临时表一次的查询，例如条件聚合或窗口计算。禁止为避免重复打开而删除连接、遗漏分支或擅自去重。
- 目标版本支持且适合时，优先由原始数据查询构造 CTE，再多次引用 CTE，替代用户临时表。不能假定给临时表套一层 CTE、视图或派生表就消除了限制，也不能仅凭更换别名保证安全；检查底层引用、优化器合并/物化行为及数据快照语义，必要时在获授权的隔离环境验证。
- 无法安全改写时，为同一语句中不同读取角色建立名称不同、物理独立的临时表副本。例如先单独执行 `CREATE TEMPORARY TABLE tmp_b LIKE tmp_a`，再执行 `INSERT INTO tmp_b (列清单) SELECT 列清单 FROM tmp_a`，最后连接 `tmp_a` 与 `tmp_b`；若有更多重复引用，逐一处理。不要把复制和多次读取源临时表塞进同一条语句。
- 副本需保留必要的列类型、精度、字符集、排序规则和索引，复制时明确列清单并处理生成列。核对复制时点；源临时表后续变化时，按原语义刷新副本或调整分阶段执行顺序，不能读取过期副本。评估数据量及复制成本，不为每张临时表无条件创建副本。
- MySQL 临时表属于会话，不会在过程返回时自动删除。明确每张表及副本的创建者、使用者和清理责任；正常结束、提前退出和异常路径都应处理本次调用拥有的临时表，异常清理后保留原错误传播。不得依赖事务回滚或连接池归还自动清除临时表。
- 仅在确认表名由本过程独占且不影响嵌套调用时，才在入口用 `DROP TEMPORARY TABLE IF EXISTS` 清理上次残留；清理必须使用 `DROP TEMPORARY TABLE`，避免误删同名永久表。`IF NOT EXISTS` 不能作为复用旧数据的借口。递归或嵌套调用需明确调用级隔离或共享契约，不能删除调用方仍在使用的临时表。
- 禁止使用永久中间表、永久暂存表或带调用标识的永久工作表绕过临时表限制，不论表名固定还是动态生成。只能采用会话级临时表、副本或等价查询改写；无法在此约束下保持语义时报告阻碍，不生成永久建表方案。

### 控制流、事务和异常
- 转换 `IF/ELSE`、`WHILE`、`BREAK/CONTINUE`、提前返回和游标时保留分支顺序；按 MySQL 规则先声明变量和条件，再声明游标和 handler，所有声明置于所属块的可执行语句之前。
- 使用有正确标签作用域的 `LEAVE/ITERATE`；过程提前退出和函数返回是不同语义。`NOT FOUND` handler 可能同时影响游标和普通 `SELECT INTO`，应限定作用域。
- 将 `TRY/CATCH`、`RAISERROR/THROW` 按目标版本映射为 handler、`SIGNAL/RESIGNAL` 和必要的诊断读取。保留异常传播、业务错误信息及清理流程，不捕获所有错误后返回成功。
- 检查显式事务、调用方事务、保存点、自动提交、隔离级别、死锁与 `XACT_ABORT`。MySQL 没有等价的嵌套事务；不能在被调用过程中无条件开启或提交事务而改变调用方边界。
- 检查 DDL 的隐式提交及临时表操作的回滚限制，不假定回滚能够撤销全部操作。`NOLOCK`、锁提示及 SQL Server 专用并发行为不能直接忽略，也不能通过擅自降低隔离级别替代。

### 动态 SQL 与特殊能力
- `EXEC/sp_executesql` 转 `PREPARE/EXECUTE/DEALLOCATE PREPARE` 时区分动态 SQL 和普通过程调用。参数绑定、可引用变量和可预处理语句以目标版本为准，确保异常路径释放预处理语句。
- 值使用参数绑定；动态表名、列名采用明确白名单和正确标识符引用。不得把字符串拼接改写成引入 SQL 注入的实现；使用会话变量时控制命名冲突及残留状态。
- XML 类型、`.value/.nodes/.query`、`FOR XML PATH` 和 XML 构造函数没有通用等价替换。必须保留原载荷结构、节点、转义和 NULL 行为，不能未经授权改为 JSON 或直接拼接未转义文本。
- SQL Server 专用的 SQL Agent、跨服务器访问、CLR、系统过程等需明确替代方案或报告阻碍，不得生成看似可执行的空壳。
- MySQL 存储函数对结果集、动态 SQL、事务操作及数据访问存在限制；无法保留函数调用方式时先确认改为过程或其他实现所需的调用方变化。

## 输出和安全边界
- 建表硬约束：存储过程中仅允许 `CREATE TEMPORARY TABLE` 创建会话级临时表，禁止在实体数据库中创建任何永久表结构。禁止普通 `CREATE TABLE`，包括 `IF NOT EXISTS`、`LIKE`、`AS SELECT` 等变体；名为 `tmp_` 的普通表仍是永久表，不属于例外。
- 上述约束同时适用于静态 SQL、动态 SQL、被调用的依赖过程和配套脚本；不得通过移到初始化脚本、另一个数据库或子过程间接建永久表。执行授权不解除此约束。需要的业务表必须已存在；源逻辑包含永久建表或目标缺少业务表时，明确报告冲突或缺失，不静默删掉该逻辑或自行补建。
- 默认保留源文件，写入用户指定的目标目录，每个对象一个 `.sql` 文件，遵循既有命名。检查已有目标文件；不得覆盖用户改动或无关文件。
- 默认按 DBeaver、mysql 命令行等支持 `DELIMITER` 的客户端生成脚本：每个过程/函数以 `DELIMITER $$` 开头、`END$$` 结尾，再以 `DELIMITER ;` 恢复；`DROP` 语句放在 `DELIMITER $$` 之前。否则客户端按分号拆分会截断过程体并报 1064。用户说明使用 JDBC/迁移工具时，改为遵循其语句分隔机制并不带 `DELIMITER`。提示用户用“执行脚本”而非单语句执行。
- 每个过程/函数的 `CREATE` 前默认加入 `DROP PROCEDURE IF EXISTS`/`DROP FUNCTION IF EXISTS`（不带数据库前缀以外的多余内容）。不默认加入硬编码 `DEFINER`、授权语句、全局设置或数据库切换；交付时说明该 `DROP` 会替换现有对象。
- 检查源 `EXECUTE AS` 和目标 `SQL SECURITY` 的权限语义，不能为方便执行而扩大权限。函数的数据访问特征及确定性声明必须真实，不能为绕过服务器限制虚报 `DETERMINISTIC`。
- 不自动新增 SQL 注释、文档说明文件或依赖安装。保留有意义的原注释，转换差异在回复中说明，用户明确要求时再写说明文档。
- 默认只读分析并生成文件；未经明确批准，不连接真实数据库、不启动数据库或容器、不部署、不执行建表、过程创建、`CALL` 或其他写操作。不得提交、推送、上传敏感源码或更改凭据。

## 核对与完成标准
- 检查所有生成脚本及必要依赖中的建表路径，包括动态拼接与条件分支，确认每处建表均为真正的 `CREATE TEMPORARY TABLE`。不得仅靠表名前缀或简单关键词搜索判定合规；发现永久建表路径时不得宣称转换完成。
- 静态逐项核对原过程与目标过程的参数、分支、结果集、类型、过滤/排序、计算、依赖调用、写入、事务和异常。搜索残留 T-SQL 关键字时须区分注释和字符串，不以“无关键字命中”作为等价依据。
- 如已有安全的隔离检查工具，先检查其行为，再使用；只连接用户明确授权的隔离测试环境。无可用环境时如实说明尚未验证目标数据库语法和运行行为，不为检查擅自安装或连接服务。
- 获得执行授权后，使用合成数据覆盖 NULL/空字符串、空结果、多行赋值、重复键、中文与尾部空格、金额精度、日期边界、关键分支、异常回滚和重复调用；需要时检查并发行为。
- 涉及临时表时，逐条核对重复引用及所有副本的生命周期；获授权后覆盖自连接、子查询和 UNION 多处引用、空表、重复行、源表更新后的副本一致性、同一连接连续调用、异常后重试、嵌套调用及不同连接并发。既确认无 `ERROR 1137`/表已存在错误，也确认结果和副作用与源逻辑一致。
- 对照两端输出时比较所有结果集、列及类型、行值、输出参数、返回状态和持久化副作用；仅在源契约保证排序时按行顺序比较，否则按保留重复次数的行集合比较。
- 必要依赖和调用适配尚未完成、语义差异尚未确认或运行验证受阻时，明确区分“已生成的脚本”与“仍未完成的迁移”，不得宣称完全等价或可直接用于生产。
