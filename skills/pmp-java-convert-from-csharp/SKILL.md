# C# 转 PMP Java 业务逻辑

先读取目标仓库适用的项目指令。如果可以访问相对于本技能目录的 `..\..\copilot-instructions.md`，也应读取其中的共享约束；此处引用不会自动加载文件。以目标仓库实际源码、构建配置和适用指令为准，不要将通知服务的基础包或 Feign 分层机械套用到其他 PMP 服务。

## 输入与适用范围
- 必须有明确的转换授权、可访问的 C# 源码或代码片段，以及可确定的 Java 目标位置。仅缺少实质性信息时提问；不要凭空补全未提供的业务规则。
- 检查源方法的直接调用、模型、枚举、扩展方法和查询实现，必要时沿调用链追踪。源依赖不可访问时，说明缺失内容和影响，不得以空实现、固定返回值或 TODO 冒充完成。
- 只修改请求涉及的仓库和功能。跨仓库转换时先确定各层归属，不得自动扩大到其他服务。

## 操作步骤
1. 从原 C# 代码提取输入输出、默认值、校验、所有条件分支、过滤/排序/分组/分页规则、金额计算、异常路径及写入或通知等副作用。在工作上下文中建立源方法与 Java 实现的对应清单，不额外生成计划或说明文件。
2. 如果没有对应的业务文档，在转换时，补充文档，如果存在业务文档，转换时同步更新，业务文档，保存路径需与用户确认
3. 检查目标 controller、service 接口及实现、Feign 契约、model 和已有工具类；涉及数据服务时再检查相关 repository。搜索已有同类逻辑，复用现有类型与工具，遵循目标项目命名和构造器注入约定，不逐字翻译 C# 命名。
3. 先检查相关现有测试并在安全可行时建立基线。按业务职责完成所有受影响层的实现和接线，保留接口字段、枚举值、响应结构与错误处理；契约差异需明确授权。
4. 重点核对下列语言语义差异，按源行为实现，不机械替换语法。无法判断的业务差异应澄清，而不是自行选择默认值。
5. 使用现有 JUnit 5/Mockito/MockMvc 为有实际业务逻辑的类补充隔离回归测试，覆盖正常、边界、异常和关键分支；不为纯字段 DTO/VO 或无逻辑接口单独生成测试。
6. 全部受影响服务的代码完成后，集中执行相关编译和测试，避免逐文件反复编译。执行前确认外部依赖已模拟；未经明确批准不得启动应用或进行真实服务集成。
7. 再次逐项对照原 C# 源码和需求，检查调用链、条件分支、计算顺序、边界、副作用及跨层字段传递，避免逻辑遗漏。检查差异，保留无关改动和未跟踪文件。

## C# 与 Java 语义核对
- 空值与默认值：区分 nullable、默认值、空字符串和空集合；核对 `??`、`?.`、`FirstOrDefault`、`SingleOrDefault` 在零条和多条结果时的行为，不能随意改为取第一条或返回空对象。
- 数值：金额和 C# `decimal` 使用合适的 `BigDecimal` 运算，明确精度、除法和舍入规则；保留整数除法和溢出处理语义，不使用 `double` 中转金额，数值相等判断须考虑 scale。
- 日期：按业务语义选择 `LocalDate`、`LocalDateTime`、`Instant` 等，核对时区、日期截断、区间开闭边界、月末和闰年；不得把本地时间与 UTC 混用。
- 查询与集合：保留 LINQ/EF 的过滤、连接、去重、排序、分组、聚合和分页先后顺序，核对空集合聚合、重复键、空值比较和数据库排序规则；不能默认 Java Stream 与数据库查询语义相同。
- 字符串与枚举：核对大小写、空白、文化区域、格式化、枚举数值及 JSON 表示；字符串值比较不用 `==`，枚举不以 ordinal 替代原业务编码。
- 执行与资源：核对 `async/await` 的执行顺序、异常传播、取消、事务边界和 `using/IDisposable` 资源释放；不为匹配语法擅自引入异步线程、重试或新的事务边界。
- 如果是关于报表生成的，请注意样式问题，如字体、粗细、背景色、边框、公式等，需要与c#源码保持一致，不仅需要检查c#代码写法，也需要参考c#导出的模板(如果存在导出模板)。

## 任务边界
- 不要把解释说明类请求变成实现任务。
- 此技能负责 C# 业务转换，不执行语言/框架升级或云平台迁移，也不擅自修正与转换无关的原代码问题。
- 不要仅因存在某项依赖就引入持久化或消息架构。
- 外部数据访问沿用目标服务既有 Feign 委托；只有目标数据服务确有仓储职责时才实现 repository，不在通知或业务服务中新增本地数据库/JPA 层。
- 保持公共接口契约不变，除非所请求的行为确实需要变更且已获得明确授权。
- 新增或修改入参 DTO/Request 时，不自动添加 `@NotNull`、`@NotBlank`、`@Pattern`、`@Min` 等 Bean Validation 校验注解，也不为此新增 `@Valid`/`@Validated`；必要的业务条件检查沿用业务服务现有方式。既有且与任务无关的校验不擅自删除。
- 报表日期入参应先参考目标仓库同类报表的类型、JSON 绑定和跨层传递方式。`reportMonth` 沿用既有 `LocalDate` 等日期类型，不因界面显示 `MM-yyyy` 而定义成 `String`，也不自行增加字符串月份解析；DTO、Feign、消息载荷及业务服务应保持类型一致。
- 不增加宽泛异常捕获、静默降级或成功形状的兜底返回；沿用现有异常处理，不记录密钥或敏感载荷。
- 在 `pmp-data-lease` 中新增/修改仓储查询时，禁止使用 `@Query` 的 HQL/JPQL/原生 SQL 字符串（含 `join fetch`）；一律通过 `XxxRepositoryCustom`/`XxxRepositoryImpl` + `CriteriaBuilder` 实现，详见共享约束文件。
- 业务查询的编排与结果组装一律放在 `pmp-service-lease`：由业务服务分别调用数据服务的单一职责查询，再完成关联、分组、聚合、计算和业务模型组装。`pmp-data-lease` 只提供简单、贴近原始数据的查询；禁止在一个数据服务方法或 Repository 方法中执行多个独立查询并拼装报表或业务结果，也不得将此类编排隐藏在辅助方法中。单次查询所需的关联、子查询以及既有分页查询的计数不属于业务查询编排。
- `pmp-data-lease` 对外返回的 VO 及其行数据类型应定义为独立顶级类，单独存放在相应 model/vo 包下，使用有业务含义的名称；不要把行 VO 定义成另一个 VO 的 `static class`，也不要返回 `TenancyExpiryScheduleReportRawDataVo.VacantUnitRow` 这类嵌套类型。提取时保留字段、构造器及 JSON 结构，同步更新 Controller、Service、Repository 投影、Feign 契约和测试中的类型与引用。此规则优先于将此类内部数据模型改写为嵌套 `record` 的建议。
- 不为方便报表查询而自动给已有实体添加集合关联或反向关联。尤其不得给 `LeaseEntity` 新增 `leaseTurnoverRents`；需要的原始数据应分别查询，并在业务服务组装，保持原有实体映射不变。
- 涉及"当前日期"默认值的设置（如查询参数缺省时补默认报表日期等）一律放在 `pmp-service-lease` 层完成，不要放在 `pmp-channel-lease` 层；且必须通过 `com.spl.pmp.service.lease.utils.DateUtils.getCurrentLocalDate()` 获取当前日期，禁止直接使用 `LocalDate.now()`。
- 编写/修改代码时不要自动添加注释或 `@Schema(description = ...)` 等接口文档注解；仅在用户明确要求时才添加。
- 新增实体字段常量时，名称使用实体类名去掉 `Entity` 后的名称作为前缀，再拼接字段名，并转换为大写下划线格式，避免与继承的常量重名。例如 `LeasePCExclusionPeriodEntity` 的 `remarks` 定义为 `LEASE_PC_EXCLUSION_PERIOD_REMARKS = "remarks"`；常量值仍为真实属性名，重命名时同步更新所有引用。
- 遵守 SonarQube 常见规则：不要使用 `record` 等受限标识符作为变量/参数名（S6213）；日期字面量优先使用 `java.time.Month` 等枚举常量而非裸整数（S8694）。
- 遵守以下常见 SonarQube 规则（"认知复杂度"S3776 规则除外，不因追求降低复杂度而做大范围重构）：重复字面量应引用已定义常量而非硬编码（S1192）；不留下未依附任何声明的悬空 Javadoc（S8491）；同一循环体内 `break`/`continue` 总数不超过 1 条，多个退出条件应合并为一个组合布尔条件（S135）；仅承载不可变字段的内部静态类，在确认访问器未被外部直接调用后可改写为 Java `record`（S6218 类建议）；`java.time.*`/`BigDecimal`/`Optional` 等 value-based 类型比较一律用 `.equals()` 而非 `==`/`!=`（`null` 判断除外，S8696）；外层 if 语句体内若只有一个内层 if（无其他语句）应合并为组合 `&&` 条件（S1066）。
- 代码中不要使用带完整包名的内联类引用（如 `com.spl.pmp.service.lease.report.utils.AsposeExcelUtils.CellStyleConfig`）；应通过 `import` 引入类型后使用简名（嵌套类沿用项目既有写法，如 `import ...AsposeExcelUtils;` 后使用 `AsposeExcelUtils.CellStyleConfig`）。
- 在 Feign 客户端接口（如 `LeaseDataClient`/`LeaseServiceClient`/`LeaseReportServiceClient`）中新增方法时，一律追加到接口末尾（最后一个已有方法之后、右花括号之前），不要插入到已有方法中间。
- 新增/修改多语言资源包（`resourcebundle/report/**/*.properties`）时，键值一律使用可读的 UTF-8 明文字符（中文直接写汉字），不要写成 `\uXXXX` 转义序列，以与项目现有资源文件保持一致的格式；写入/修改后应人工核对文案本身是否正确（无错别字、简繁体混用等），不能仅满足编译通过。
- 任务中修改过的代码，如果用户进行修改的内容，不要擅自删除或覆盖；仅在用户明确要求或与用户确认时才修改已有代码。若用户要求删除/覆盖，需说明理由和影响，并在交付时提供原始内容的备份。
- 业务逻辑上，要与原代码业务逻辑保持一致，不得擅自更改、简化或删除原有逻辑；若用户要求更改或删除，需说明理由和影响，并在交付时提供原始内容的备份。
- java代码中对于空值的判断，尽量不用`== null`，而是使用`Objects.isNull()`或`Objects.nonNull()`等，以提高代码可读性和一致性。
- java代码中，对于报表查询的数据存在多语言的情况，我们不在pmp-data-lease和service去处理多语言，我们一般返回结果后在pmp-service-lease-report中去处理。

## 证据与完成标准
交付时简要说明完成的转换、源代码与 Java 实现的对应关系、接口契约影响及经授权的行为差异。源逻辑覆盖和相关检查均完成才可声称完成；缺失源码、私有依赖解析失败或其他阻碍必须如实说明，不能将未执行或受阻的验证描述为成功。不得为解决依赖问题安装、更改或泄露凭据。
